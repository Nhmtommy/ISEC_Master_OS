# ISEC: Integrated Software Engineering Curriculum

## Overview

This repository is a public, verifiable record of a rigorous 365-day software engineering independent study. It documents the daily execution of a first-principles curriculum covering computer science fundamentals, systems architecture, and full-stack development.

The goal is not merely to learn syntax, but to develop the engineering discipline required to design, build, test, and maintain reliable software systems.

## The Daily Standard

Every commit in this repository represents a completed day of study. The protocol enforces a strict daily standard. Inside each day's folder (e.g., `Phase-1-Foundations/Day-001-Topic/`), you will find:

1. **`hands_on.py`**: The runnable code typed for the daily lesson.
2. **`debug_exercise.py`**: Deliberately broken code that was debugged and fixed to prove root-cause analysis.
3. **`build_task.py`**: The standalone application written from scratch to solve the day's engineering challenge.
4. **`daily_report.md`**: A formal report documenting bug analysis, edge-case testing, engineering trade-offs, and a signed declaration of original work.
5. **Big Book Scan**: A photograph of the handwritten Feynman explanation, program trace, and edge cases recorded in the physical Big Book.

## Curriculum Architecture

The curriculum is divided into four distinct phases:

- **Phase 1: Foundations & Code** (Days 1–90)
  Python, C, Discrete Mathematics, Computer Architecture, Data Structures, Algorithms, and Operating Systems.
- **Phase 2: Core Engineering** (Days 91–180)
  Software Architecture, HCI, Databases, Networking, Verification & Validation, and Project Management.
- **Phase 3: Advanced Topics** (Days 181–270)
  Formal Methods, Cloud Computing, Security, Machine Learning, and specialized electives.
- **Phase 4: Capstone & Mastery** (Days 271–365)
  Full-scale system design, implementation, testing, and deployment of a production-grade application.

## Professional Standards

This repository adheres to strict engineering standards:

- **Code Quality:** PEP 8 compliant, modular, and documented.
- **Version Control:** Meaningful commit messages (Conventional Commits).
- **Testing:** Edge cases are deliberately tested and documented.
- **Documentation:** Every day includes a formal `daily_report.md`.
- **Integrity:** No AI-generated core logic without citation. All code is typed by hand and fully understood.
